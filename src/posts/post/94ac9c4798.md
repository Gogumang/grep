### 쿠폰, 어디에 쓸 수 있어요? --- 이벤트 기반 적용 상품 조회 시스템 구축

안녕하세요, 29CM Commerce Core Engineering 에서 Sale Pricing 팀으로 일하고 있는 백엔드 개발자 조한석이라고 합니다.

저는 주로 쿠폰, 결제혜택 등 할인과 가격 도메인을 개발하고 있는데요, 쿠폰 시스템을 개발하고 관리하면서 사용자들로부터 가장 많이 받았던 질문이 있습니다.
> "이 쿠폰은 어떤 상품에 쓸 수 있어요?"

이 질문은 오랫동안 29CM 사용자들이 쿠폰과 관련해 가장 자주 문의한 내용 중 하나였습니다.

유저의 쿠폰함에서 보유한 쿠폰을 확인할 수 있지만, 해당 쿠폰을 어떤 상품에 적용할 수 있는지 확인할 방법이 없었습니다. 그래서 지금까지 사용자들은 쿠폰 사용처를 찾기 위해 일일이 상품 페이지를 방문하며 확인해야 했습니다. 🥲

2025년 2월, 마침내 오랜 숙원과 같았던 **쿠폰 적용 가능 상품 목록 조회** 기능을 론칭하게 되었습니다!
> '쿠폰 적용 가능 상품 목록'

겉보기엔 단순히 쿠폰과 연결된 상품 목록을 조회해 보여주는 간단한 기능처럼 보일 수 있지만, 실제로는 예상보다 훨씬 복잡한 과제였습니다.

### 쿠폰 적용 가능 상품 조회의 어려움

**1️⃣ 쿠폰과 상품 설정을 모두 고려해야 하는 복잡성**

쿠폰 설정 시 특정 상품들을 쿠폰 적용 대상으로 매핑하지만, 이것만으로는 실제 적용 가능 여부를 완전히 결정할 수 없었습니다. 왜냐하면,

* 상품에는 판매가, 쿠폰 허용 여부 같은 개별 설정이 존재합니다.
* 쿠폰에 상품이 매핑되어 있더라도 이러한 상품 설정에 따라 쿠폰 적용이 제한될 수 있습니다.

따라서 쿠폰 적용 가능 상품을 정확히 판단하려면, 쿠폰에 설정된 상품 목록만 확인해서는 안 됩니다. 쿠폰 설정과 상품의 개별 설정을 함께 검증하는 복합적인 로직이 필요합니다.

**2️⃣ 실시간으로 변화하는 쿠폰 적용 조건**

쿠폰과 상품 간의 관계는 고정되어 있지 않고 지속적으로 변화합니다.

* 쿠폰이 활성화된 상태에서도 적용 가능한 상품 목록은 운영 정책에 따라 수시로 변경됩니다.
* 상품의 판매가는 할인 스케줄에 따라 자주 업데이트되며, 이는 쿠폰 적용 가능 여부에 직접적인 영향을 미칩니다.

따라서 쿠폰 적용 가능 상품은 한 번 결정되면 변하지않는 정적 정보가 아닌, 실시간으로 변동하는 동적 데이터입니다. 이로 인해 사용자가 조회하는 시점의 최신 쿠폰 및 상품 정보를 기반으로 적용 가능 여부를 실시간으로 판단해야 하는 기술적 과제가 존재했습니다.

**3️⃣ 복잡한 쿠폰 매핑 방식에 대한 대응**

쿠폰 설정에는 다양한 매핑 방식이 있으며, 그중에서도 특히 까다로운 방식은 '제외 매핑'이었습니다.

* 제외 매핑 방식은 "이 상품들을 제외한 모든 상품에 쿠폰이 적용 가능" 한 형태로 설정됩니다.
* 이 경우, 시스템은 특정 상품을 제외한 29CM의 모든 활성 상품(수십만 개 이상)을 대상으로 판단하고 처리해야 합니다.
* 또한 새로운 상품이 등록되거나 비활성 상품이 재활성화될 경우에도 자동으로 쿠폰 적용 대상에 포함되어야 했습니다.

이러한 '포괄적 적용 + 예외 처리' 방식은 단순 매핑보다 훨씬 더 복잡한 로직과 높은 확장성을 요구했으며, 시스템 설계 과정에서 가장 큰 도전 과제 중 하나였습니다.

**4️⃣ 기존 상품 검색 경험과의 일관성 유지 필요**

사용자 경험 측면에서 쿠폰 적용 가능 상품 목록 역시 29CM의 기존 상품 목록 페이지(PLP, SRP)와 동일한 사용성을 제공해야 했습니다.

* 사용자들이 이미 익숙한 카테고리, 가격대, 브랜드 필터를 그대로 활용할 수 있어야 했습니다.
* 인기순, 최신순, 가격순 등 기존과 동일한 정렬 옵션 또한 제공되어야 했습니다.

이를 위해, 상품별 쿠폰 적용 가능 정보를 Elasticsearch(ES)에 인덱싱하는 구조를 설계하여 기존의 필터링, 정렬, 페이지네이션 기능을 완벽하게 지원할 수 있도록 했습니다.

### 쿠폰 적용 가능 상품 목록 조회를 위한 핵심 요구사항

앞서 설명한 복잡한 상황을 해결하기 위해 다음과 같은 핵심 요구사항을 도출했습니다.

1. **실시간 데이터 동기화** --- 쿠폰 및 상품 설정 변경 시, 적용 가능 여부 정보가 즉시 반영되어야 합니다.
2. **다양한 매핑 방식 지원** --- '제외 매핑'과 같은 복잡한 쿠폰 설정에서도, 신규 상품 등록 또는 기존 상품 변경 시 적용 가능 여부가 자동으로 반영되어야 합니다.
3. **검색 최적화를 위한 인덱싱** --- 사용자 경험과 성능 향상을 위해, 상품별 쿠폰 적용 가능 정보를 Elasticsearch에 인덱싱하여 빠른 검색 및 필터링을 지원해야 합니다.

이러한 요구사항은 단순한 데이터 조회를 넘어서는, 복잡한 시스템 구축이 필요함을 명확히 보여주었습니다.

### 설계 및 구현: 이벤트 기반 실시간 데이터 처리 시스템

앞서 언급한 도전 과제와 요구사항을 충족하기 위해, 다음과 같이 이벤트 기반 아키텍처를 중심으로 한 실시간 데이터 처리 시스템을 설계하고 구현했습니다.
![](https://cdn-images-1.medium.com/max/1024/1*YuvGchxhGaHBVDRQQB6PkA.png)전체 구조 및 흐름

**1️⃣ \[A.쿠폰 적용 가능 상품 갱신\] 메시지 발행**

* 상품 또는 쿠폰의 생성/수정 이벤트가 발생할 때마다 **A.쿠폰 적용 가능 상품 갱신** Kafka 토픽에 메시지를 발행합니다.

![](https://cdn-images-1.medium.com/max/1024/1*0S2Tz0Hgph-JGnuxijB-vg.png)A.쿠폰 적용 가능 상품 갱신 Topic Message

* 메시지에는 갱신 대상이 되는 '쿠폰-상품' 쌍 정보가 포함됩니다.
* 상품 변경 시에는 해당 상품과 연결된 모든 활성 쿠폰에 대한 메시지가 발행됩니다.
* 쿠폰 변경 시에는 해당 쿠폰이 적용 가능한 모든 관련 상품에 대한 메시지가 발행됩니다.

**2️⃣ \[A.쿠폰 적용 가능 상품 갱신\] 메시지 소비 및 데이터 갱신**
![](https://cdn-images-1.medium.com/max/1024/1*A8ORkoYQTQ0GfekyYaQZ_Q.png)쿠폰 적용 가능 상품 반정규화 Table

* **Coupon-Event-Worker**는 토픽의 메시지를 소비하여 각 '쿠폰-상품' 쌍에 대한 적용 가능 여부를 판별합니다.
* 적용 가능한 경우: 해당 '쿠폰-상품' 쌍을 **쿠폰 적용 가능 상품 반정규화 Table**에 저장합니다.
* 적용 불가능한 경우: 테이블에 해당 데이터가 존재하면 삭제하고, 존재하지 않으면 아무 작업도 수행하지 않습니다.

**3️⃣ \[B.쿠폰 적용 가능 상품 CDC\] 메시지 발행**

* **Debezium**을 활용해 반정규화 테이블의 모든 변경 사항(삽입/수정/삭제)을 캡처합니다.
* 캡처된 변경 사항은 **B.쿠폰 적용 가능 상품 CDC** Kafka 토픽으로 자동 발행됩니다.
* 이를 통해 반정규화 테이블의 모든 데이터 변동을 실시간으로 추적할 수 있습니다.

![](https://cdn-images-1.medium.com/max/1024/1*7OI1n9Jev-GzLTqWc3qvFw.png)B.쿠폰 적용 가능 상품 CDC Topic Message

**4️⃣ \[C.쿠폰 적용 가능 상품 싱크\] 메시지 발행**

* **Coupon-Event-Worker**는 CDC 토픽의 메시지를 소비해 변경된 상품을 식별합니다.

![](https://cdn-images-1.medium.com/max/1024/1*oOG9TPI0-8zkClv1I3cK-Q.png)C.쿠폰 적용 가능 상품 싱크 Topic Message

* 각 상품에 적용 가능한 전체 쿠폰 목록을 반정규화 테이블에서 조회합니다.
* 해당 상품 ID와 적용 가능한 쿠폰 목록을 **C.쿠폰 적용 가능 상품 싱크** Kafka 토픽에 메시지로 발행합니다.

**5️⃣ Elasticsearch에 최종 결과 인덱싱**

* **ES-Indexer**는 싱크 토픽의 메시지를 소비합니다.
* 각 상품 ID와 해당 상품에 적용 가능한 쿠폰 목록을 **Elasticsearch**에 인덱싱합니다.
* 이를 통해 상품 검색 시 쿠폰 적용 가능 여부로 필터링하거나 정렬할 수 있게 됩니다.

위 설계 및 구현 내용을 간단히 요약하자면,
![](https://cdn-images-1.medium.com/max/1024/1*nVSPUaFYgcpEl0h2HaGvIw.png)설계 및 구현 내용 요약

* 쿠폰 적용 가능 상품 정보를 저장하는 반정규화 테이블을 구축했습니다.
* 상품 또는 쿠폰에 변경이 발생할 때마다, 해당 내용을 Kafka로 즉시 발행합니다.
* 발행된 메시지는 실시간으로 처리되어, 반정규화 테이블 데이터를 최신 상태로 유지합니다.
* 반정규화 테이블 정보를 기반으로, 각 상품에 적용 가능한 쿠폰 목록을 Elasticsearch에 인덱싱하여 빠른 검색과 필터링을 가능하게 합니다.

결과적으로 이러한 구조를 통해 앞서 언급한 요구사항들을 성공적으로 충족할 수 있었습니다.

* 쿠폰 또는 상품 설정이 변경될 때마다, 즉시 메시지가 발행되어 반정규화 테이블이 실시간으로 갱신됩니다. 이를 통해 쿠폰 적용 가능 정보가 항상 최신 상태로 유지됩니다.
* '상품-쿠폰' 쌍 형태로 데이터를 반정규화 테이블에 저장함으로써, 포함 매핑, 제외 매핑 등 **다양한 쿠폰 매핑 방식을 동일한 구조**로 효과적으로 표현할 수 있게 되었습니다.
* 반정규화 테이블의 데이터를 **Elasticsearch에 인덱싱**하고 CDC를 통해 지속적으로 갱신함으로써, 상품별 적용 가능 쿠폰 목록을 빠르게 검색하고 필터링할 수 있게 되었습니다.

설계 과정에서 '쿠폰 적용 가능 상품 반정규화 테이블'의 추가적인 활용 가치도 중요하게 고려했습니다.

쿠폰 도메인에서 가장 빈번하게 사용되는 로직 중 하나는 **특정 상품에 특정 쿠폰이 적용 가능한지 판단**하는 것입니다. 기존에는 이런 판단을 위해 여러 테이블을 조회하고 복잡한 조건식을 계산해야 했습니다. 이러한 방식은 성능 저하와 유지보수의 어려움을 동시에 초래했습니다.

하지만 이번에 구축한 반정규화 테이블과 실시간 데이터 갱신 시스템 덕분에, 이제는 단일 테이블 조회만으로도 쿠폰 적용 가능 여부를 즉시 확인할 수 있게 되었습니다. 이는 단순히 하나의 기능 개선에 그치지 않고, 쿠폰 서비스 전반의 성능과 안정성을 크게 향상시키는 기반이 되었습니다.

결과적으로 본 프로젝트를 통해 초기 목표였던 쿠폰 적용 가능 상품 목록 조회 기능뿐만 아니라, 쿠폰 도메인 전반의 기능 개선까지 성공적으로 이끌어냈습니다.

### 개발 과정에서 마주한 어려움

복잡한 쿠폰 매핑 구조와 실시간 갱신의 필요성으로 인해 설계 과정에서 몇 가지 어려움이 있었습니다.

**🔸 반복된 설계 변경**

쿠폰의 다양한 매핑 유형과 상품 변경 시에도 발생하는 갱신 요구로 인해, 초기에는 여러 Batch를 병렬로 운영하는 구조를 고려했습니다.

그러나 팀 내 피드백을 반영해 설계가 여러 차례 변경되었고, 그 결과 현재의 이벤트 기반 구조로 수렴하게 되었습니다. 복잡한 도메인 정책과 까다로운 요구사항에 맞춰 반복적으로 설계를 조정해야 했던 점이 특히 어려웠습니다.

**🔸 메시지 처리 최적화**

초기 구현 당시, 단순한 로직으로 인해 지나치게 많은 메시지가 발행되면서 소비 속도에 병목이 발생했습니다. 이 문제를 해결하기 위해 다음과 같은 시행착오를 거쳤습니다.

* Batch Consuming 방식 도입
* Kafka 설정 튜닝을 통한 처리량 개선
* 갱신 대상에 한해 메시지를 발행하도록 로직 개선
* Batch Consuming 시 효율적인 처리를 위한 소비 로직 최적화

이러한 다단계 최적화 과정을 통해, 대용량 데이터 환경에서도 실시간에 가까운 갱신 성능을 확보할 수 있었습니다.

복잡한 도메인 로직과 대용량 데이터 처리라는 두 과제를 동시에 해결해야 했던, 도전적인 여정이었습니다.
