## Fixed IP vs Floating IP

지난달 뉴스레터에서는 VPC를 이용해 이를 통해 격리된 환경의 인프라 운영이 가능하다는 설명을 드렸는데, 이번달에는 VPC 내부 망에서만 사용할 수 있는 사설 IP와 외부에서 접근할 수 있는 공인 IP 두가지에 대해서 설명을 드리려고 합니다.

TOAST에서는 사설/공인 IP 모두를 지원하고 있으며, 각각 Fixed IP/Floating IP로 서비스를 제공하고 있습니다.

|       구분       |  Fixed IP (사설)  | Floating IP (공인) |
|----------------|-----------------|------------------|
| 서비스 내 IP 할당 방식 | DHCP            | 사용자 지정           |
| 유효구간           | VPC 내부에서만 접근 가능 | VPC 외부에서 접근 가능   |

**Fixed IP** VPC의 서브넷 내에서 할당되는 Fixed IP는 인스턴스 생성시 DHCP(Dynamic Host Configuration Protocol)를 통해 자동으로 할당됩니다. (자세한 동작은 DHCP 동작을 참고)

Fixed IP는 서브넷 내에서만 유효한 주소이나, VPC가 같다면, VPC Routing 기능을 이용해 다른 서브넷과 연결이 가능합니다.

이렇게 자동으로 할당된 Fixed IP는 VPC 내에서 인스턴스를 식별하기 위해 사용할 수 있지만, 인터넷을 통한 외부에서의 접근은 불가능합니다.

**Floating IP** 외부에서 인스턴스에 접근하기 위해, 인스턴스에 공인 IP가 할당되어야 하며, TOAST에서는 Floating IP 서비스를 통해 공인 IP를 이용할 수 있습니다.

* Floating IP는 사용자 계정에 속한 자원입니다.
* 인스턴스를 삭제하더라도 인스턴스와 연결만 해제 될 뿐, 할당 받은 Floating IP가 삭제되지 않습니다.
* 연결 해제된 Floating IP는 다른 인스턴스에 할당할 수 있습니다.

그림 1과 같이 Floating IP 연결 메뉴를 통해 인스턴스 또는 로드밸런서와 Floating IP 연결이 가능하며, 내부 동작은 아래 그림 2와 같습니다.

![2.png](https://images.gogumang.com/895edb5210/02.png) (그림 2) Floating IP 내부 동작

인스턴스에 Floating IP가 할당되면, 내부적으로 NAT를 통해 Floating IP와 Fixed IP를 맵핑하게 됩니다. 직접적으로 Floating IP를 인스턴스에 할당하는 대신 NAT를 통해 할당함으로써, 인스턴스 재시작없이 같은 Floating IP 연결을 동적으로 진행할 수 있습니다.

**참고) DHCP 동작** **1. Discover** 인스턴스 부팅시, 브로드캐스트 메시지를 통해 DHCP 서버에게 IP 할당을 요청합니다.

**2. Offer** DHCP 서버는 인스턴스로 부터 받은 메시지에 대해 후보 IP를 지정해서 응답합니다. 해당 IP의 할당은 유효 시간이 있으며, Offer 시 함께 제공됩니다.

**3. Request** 인스턴스는 DHCP 서버로 부터 온 Offer에 대해 승인/거절 할 수 있는데, 거절 시 Discover를 다시 수행하게 되며, 승인시 Request 상태가 되며 서버에게 해당 IP를 할당 요청합니다.

**4. Ack** DHCP 서버는 Ack를 통해 IP 할당을 완료합니다.

![3.png](https://images.gogumang.com/895edb5210/03.png) 할당 받은 IP의 유효 시간이 가까이 오면 인스턴스는 자동으로 IP 갱신 요청을 서버로 보내게 됩니다. 이때는 Discover와 Offer 과정 없이 Request, Ack 만으로 갱신이 마무리 됩니다.
