### 왜 MSK를 도입했나요?

해외숙소 서비스는 많은 개발팀의 협업이 필요한 프로젝트였습니다. 저희는 이벤트를 기반으로 상품, 쿠폰, 리뷰 등의 데이터를 송수신 할 수 있는 시스템이 필요하였고 그 후보군으로 [AWS SQS](https://docs.aws.amazon.com/AWSSimpleQueueService/latest/SQSDeveloperGuide/welcome.html), [Apache Kafka](https://kafka.apache.org/), [AWS MSK](https://docs.aws.amazon.com/msk/latest/developerguide/what-is-msk.html), [AWS Kinesis](https://docs.aws.amazon.com/streams/latest/dev/introduction.html) 등의 서비스를 고려하였습니다. AWS SQS는 성능이 낮아서 검토 대상에서 가장 먼저 제외하였고, AWS Kinesis는 관리가 편하고 사용하기 쉬운 장점은 있지만 기존 개발자들이 경험이 많아서 익숙한 Kafka를 도입하기로 하였습니다.

### Amazon MSK란 무엇인가요?

Amazon Managed Streaming for Apache Kafka(Amazon MSK)는 Apache Kafka를 사용하여 스트리밍 데이터를 처리하는 애플리케이션의 구축 및 실행을 위해 사용할 수 있는 완전관리형 서비스입니다. Amazon MSK는 Apache Kafka 커뮤니티의 기존 애플리케이션, 도구 및 플러그인이 지원되므로 애플리케이션 코드를 변경할 필요가 없습니다.

아래 그림은 Amazon MSK의 구성요소입니다.

![](https://images.gogumang.com/6a760157c6/03.png)

**MSK 구성요소**

Broker

* Amazon MSK 클러스터를 생성할 때 Amazon MSK가 각 가용 영역에 생성할 브로커 노드 수를 지정합니다.
* 클러스터에는 가용 영역당 하나의 브로커가 있습니다. 각 가용 영역에는 고유한 virtual private cloud(VPC) 서브넷이 있습니다.

ZooKeeper

* 아마존 MSK는 아파치를 생성합니다.
* ZooKeeper 노드를 사용할 수 있습니다.
* 아파치 ZooKeeper 는 안정성이 뛰어나고 분산 조정을 지원하는 오픈 소스 서버입니다.

Producers, Consumers, and Topic Creators

* Amazon MSK를 사용하면 Apache Kafka 데이터 영역 작업을 사용하여 Topic을 만들고, 데이터를 생산하고 소비할 수 있습니다.

### MSK 비용 검토

AWS 서울 리전 기준으로 EC2 기반 Apache Kafka 클러스터 구축 시 비용과 Amazon MSK의 대략적인 비용을 검토해보겠습니다.

* EBS는 100GB를 기준으로 산정하였으나, 크기에 따라 비용이 달라질 수 있습니다.
* 데이터 전송 비용은 고려하지 않았습니다.
* MSK의 경우 Apache ZooKeeper 노드 또는 클러스터 내의 브로커 간이나 Apache ZooKeeper 노드와 브로커 간에 발생하는 데이터 전송에 대해서는 비용을 지불하지 않습니다.
* EC2는 복제할 브로커가 다른 가용영역에 있다면 비용이 발생합니다.
* 즉, 동일 고가용성 구성으로 여러 가용영역에 걸쳐 브로커를 구축하면 네트워크 비용은 MSK가 저렴합니다.

비용은 [AWS pricing calculator](https://calculator.aws/#/)를 사용하여 산정하였습니다.

EC2에 직접 구축하는 것보다 완전관리형인 MSK를 사용하면 비용이 많이 듭니다. 인스턴스 타입 m5.large 기준으로 보면 EC2 3대로 구축하는 경우보다 MSK로 구축 시 약 2배 정도 비용이 많이 든 걸 알 수 있습니다. MSK 브로커 인스턴스가 비싸게 책정되어 있고 현재는 예약 인스턴스 요금까지 제공하지 않고 있어서 비용이 더 비싸게 느껴지는 것 같습니다.
> Q: Amazon MSK에서 예약 인스턴스 요금을 제공하나요?
>
>
> A: 아니요. 현재는 아닙니다.
>
>
> <https://aws.amazon.com/ko/msk/faqs/>

예를 들면 AWS EMR 서비스의 경우는 인스턴스 타입마다 다르지만, 예약 인스턴스를 사용하는 경우 약 20\~30% 정도의 비용을 저렴하게 사용할 수 있는 것과 비교하면 MSK의 경우 비용면에서는 아쉬운 부분이 있습니다.

하지만 비용을 비교할 때는 고려해야 할 사항이 많이 있습니다.

EC2에 직접 구축하면 시간도 많이 소요되고, 숙련된 엔지니어가 필요하므로 인건비도 고려해야 합니다. 또한 이슈가 발생했을 때 분석에 필요한 시간, 서비스 장애 시 매출 하락 등의 많은 요소도 고려가 필요하다고 생각합니다. MSK를 활용하면 빠르게 클러스터를 구축 할 수 있으며, 확장성(디스크/브로커)이 좋고, 업그레이드도 쉬워서 운영 및 관리가 쉽습니다. 종합적으로 검토 후 최적화해서 사용한다면 저렴하게 사용할 수 있을 것으로 판단되어 MSK를 도입하기로 내부적으로 의사결정하였습니다.

실제로 개발 환경의 경우는 최소 인스턴스 타입(t3.small)으로 broker의 개수도 최소인 2개를 사용하여 구축하였습니다. 트래픽 규모가 크지 않다면 개발 환경에서 전혀 무리 없고, 성능도 꽤 잘 나옵니다. 이 부분은 PART 2 성능 테스트 부분에서 좀 더 다루어보도록 하겠습니다.

AWS 공식 문서에는 EC2 기반 Apache Kafka 클러스터와 Amazon MSK의 비용에 관한 추정치를 제공하고 있습니다. 클러스터 성능, 크기 및 비용은 사용 사례에 따라 다르며 실제 테스트를 통해 확인해야 한다고 언급하고 있습니다. [**MSK_Sinzing_Pricing 문서**](https://dy7oqpxkwhskb.cloudfront.net/MSK_Sizing_Pricing.xlsx)를 보면 Replication, Zookeeper, 엔지니어 비용을 포함하면 MSK가 오히려 비용이 저렴하다는 내용인데 참고하시면 도움이 될것 같습니다.
