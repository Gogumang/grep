부제. 새로운 지역 탐색 경험의 탄생

![](https://images.gogumang.com/c7edf7c508/01.png)

서비스를 개선하기 위해 기존 기능을 강화하거나 새로운 아이디어를 제안하는 일은 흔합니다. 이번 글은 선행으로 시작한 프로젝트를 정규 프로젝트로 전환시켰던 ‘카테고리 홈 개선기’를 공유해보려 해요.

### **왜** **카테고리 홈에 검색 기능이 추가되었을까?**

서비스 퀄리티를 관리하기 위해 주기적으로 UT를 진행하고 있어요. 여러 UT를 진행하면서 발견한 주요 문제 중 하나는 바로 카테고리 홈에서 지역 탐색이 어렵다는 점이었어요.

고객은 특정 지역만 선택하고 싶어 하지만, 제공되고 있는 지역 그룹 구조상 원하는 지역을 고를 수 없었어요. 또, 명소 기준으로 검색하고 싶어도 행정 구역에 익숙하지 않아 탐색에 불편함을 느낄 수 밖에 없었죠. 예를 들어, “가로수길이 신사동인지 논현동인지 헷갈린다”거나 “여수가 어떤 상위 지역에 속하는지 몰라 어렵다” 그리고 “홍대 지역만 보고 싶은데 선택이 안 된다”는 피드백이 대표적이었죠.

```
카테고리 홈이란?
여기어때 홈에서 호텔, 모텔 등 '숙소 유형'을 선택하면 나오는 페이지예요. 이하 '카홈'으로 지칭합니다.
```

![](https://images.gogumang.com/c7edf7c508/02.png)

*개편 전 카테고리홈*

이 문제는 서로 연관성이 낮은 지역들을 하나의 그룹으로 묶어 제공하는 방식에서 비롯되었지만, 내부 비즈니스 제약으로 인해 지역의 상/하위 체계를 즉시 개선하기는 어려웠어요. 이에 따라, 기존 지역 그룹 구조를 유지한 상태에서 카홈의 UX를 개선하는 방안이 필요했죠.

또한, 기존 카홈에서는 지역 탐색 기능이 여러 위치에 흩어져 있었고, 카테고리별로 제공되는 탐색 도구도 일관성이 부족했어요. 예를 들어, 지하철 검색 기능은 모텔 카테고리에서만 지원되는 등 사용자가 탐색 과정에서 불편을 겪고 있었죠. 이러한 복합적인 문제를 해결하기 위해 카홈에 **검색 기능**을 추가하는 방안을 제안하게 되었어요.

### **선택의 폭을 좁혀주는 차별화된 검색 결과**

결론적으로 모든 카홈에서 “지역명/명소/지하철역/숙소명” 키워드를 활용한 탐색이 가능해졌어요. 이 검색 기능은 기존 통합 검색(하단 네비게이션)과 차별점이 있어요. 통합 검색은 모든 카테고리를 아우르는 결과를 제공하는 반면, **카테고리 홈의 검색은 선택한 카테고리 내에서만 결과를 보여주는 방식이에요.** 예를 들어, 펜션 카테고리 홈에서는 펜션과 관련된 결과만을 보여주어 고객이 원하는 조건 안에서 더 집중적으로 탐색할 수 있도록 설계했죠.

이 차별화는 소소해 보일 수 있지만, **분산된 기능을 한곳으로 집중시켜 더 빠르고 좁은 검색 결과로 도달**하게 함으로써 탐색 경험을 개선할 수 있을 거라 기대했어요.

![](https://images.gogumang.com/c7edf7c508/03.png)

*카테고리 내에서만 결과 노출*

### **Casual UT를 통한 초기 검증하기**

모텔 카테고리에서 첫 실험을 진행했어요. 모텔에서 기능 검증을 마친 후 다른 카테고리로 확장할 계획이었고, 동시에 ‘내 위치 기반 주변 추천 숙소’ 모텔 모듈의 기능 검증도 필요했어요. 이를 위해 기존 페이지에 검색 기능을 추가하여 큰 디펜던시 없이 모듈을 유지하는 방안을 고려했어요.

이를 캐주얼 UT를 통해 사용성을 검증했는데, 예상하지 못한 문제들이 나타났어요.
> 1. 사용자들이 검색 기능을 잘 발견하지 못했고
>
>
> 2. 모듈의 기능을 오해하는 경향이 있었어요.

대부분의 사용자가 ‘내 위치’ 버튼을 누르면 페이지 하단 전체가 주변 숙소로 업데이트될 것으로 기대했지만, 실제로는 해당 모듈 내에서만 위치 기반 추천이 이루어지는 구조였죠. 사용자는 위치를 수정하려고 페이지를 여러 차례 탐색하다가 결국 검색 기능 또는 지역 리스트를 확인하는 패턴을 보였어요. 이를 통해 기존 모듈의 수정이 필요하다는 결론에 도달했죠.

이 문제를 해결하기 위해 다음과 같은 개선 방안을 마련했어요.
> 1. 모듈 타이틀 오른쪽에 ‘내 위치’ 버튼을 배치하고
>
>
> 2. 타이틀을 ‘주변 추천 숙소’로 명확하게 변경했어요.
>
>
> 3. 하단의 ‘검색 기능/지역 리스트’와 시각적으로 구분되게 배경색을 추가하여 사용자가 쉽게 인지할 수 있도록 개선했어요.

![](https://images.gogumang.com/c7edf7c508/04.png)

*카테고리홈 수정 후 시안*

### **AB 테스트로 실전에서 검증하기, 그 결과는?**

모텔 카테고리 홈에 검색 기능을 추가하고, Casual UT 이후 개선 된 ‘주변 추천 숙소’ 모듈을 반영했어요. 결과적으로 GMV per User가 기존 대비 유의미하게 상승했어요. 이는 기존 카홈에서 고객들이 지역 탐색 과정에서 겪었던 불편함이 크게 개선되었음을 보여주었어요.

1차 검증이 성공적으로 완료된 모텔 카테고리를 시작으로, Phase2에서는 비모텔 카테고리로 개선 범위를 확장했어요. 놀랍게도 비모텔 카테고리에서 모텔보다 더 높은 GMV 증가를 기록하며, 솔루션의 효과를 최종적으로 검증할 수 있었어요. 이 결과는 고객 입장에서 문제를 제대로 해결하고 솔루션을 잘 적용하면, 서비스 성과도 자연스럽게 따라온다는 걸 보여준 사례이기도 했어요.

### **선행 프로젝트에서 시작된 변화**
각개전투는 그만, 이제는 숲을 봐야 할 때

사실 이 솔루션은 2023년 하반기에 진행된 선행 프로젝트에서부터 시작되었어요. 각 도메인별로 빠르게 실험을 하며 고도화를 진행하다 보니 일관되지 않은 고객 경험이 생겨났고, 서비스 전반적인 사용성 검토 필요성이 대두되었죠. 이를 해결하기 위해 숙박 카테고리를 중심으로 고객의 전반적인 탐색 경험 개선을 목표로 선행 프로젝트를 진행하게 되었어요.

### **폭넓게 바라보고, 깊이있게 파헤치기:**
**Persona \& User story \& PPF의 활용**

우리는 프로젝트 초기에 정말 다양한 프레임워크를 활용하여 문제를 발굴하고 정의했어요. 선행 프로젝트다 보니, 서비스를 보다 더 폭넓게 바라보고 문제를 경계없이 발견하고자 했기에 더 유용하게 활용할 수 있었어요.

여기어때 서비스를 이용하는 고객군은 매우 다양해요. 모든 고객들을 타겟으로 하기엔 현실적으로 한계가 있죠. 대신 핵심 고객층 대상, 심도있는 데이터 기반으로 정의된 ‘여기어때만의 퍼소나’가 있었어요. 일관된 목표로 서비스를 유지하고 개선할 수 있도록 기준이 되는 프로덕트의 등대같은 존재죠. 이 퍼소나별로 수십가지의 유저 스토리를 설계하여, 고객이 여기어때를 이용하면서 겪는 여정을 살펴보았고, 평소 메이커의 입장으로는 생각치 못했던 부분, 익숙한 패턴인데 자사에서만 다르게 제공하고 있는 경험 등 우리 서비스를 한층 더 새롭게 바라볼 수 있었고 수많은 인사이트들을 얻게 되었죠.

그 과정에서 150여 개의 페인포인트를 발견했고, PPF를 활용해 고객이 느끼는 불편함의 정도를 수치화하여 문제의 중요도를 파악할수도 있었어요. PPF로 점수를 하나하나 매기다 보니, 자연스레 작업자 간에 커뮤니케이션이 깊어지며, 전반적인 문제에 대한 기준을 세울 수 있어서 더 유용하게 활용할 수 있었어요. 이렇게 점수가 매겨진 페인포인트들을 유형별로 그룹화하여 핵심이 되는 키워드들을 도출했어요. 그 결과, ‘지역 이해도’, ‘탐색 도구의 사용성’, ‘상품 탐색’ 등이 주요 문제 상황으로 정의할 수 있었고 BRICE를 기준으로 우선순위도 설정할 수 있게 되었죠.

***\*PPF(Problem Prioritization Formula)란?***

*고객 문제점의 치명성을 3등급(병목/마찰/번거로움)으로 분류하는 프레임워크예요.*

*자세한 내용은 [이 글](https://medium.com/gccompany/k-%ED%8C%80%EC%9E%A5%EC%97%90%EC%84%9C-%EC%A7%84%EC%A7%9C-%ED%8C%80%EC%9E%A5%EC%9C%BC%EB%A1%9C-%EA%B1%B0%EB%93%AD%EB%82%98%EA%B8%B0-98d6e726ae73)을 확인해주세요.*

### **눈에 보이는 명확한 솔루션으로 리더십 설득하기:**
**Internal Memo \& Journey map \& Prototyping의 활용**

문제를 발굴하고 솔루션을 설계하는 과정에서 Internal memo를 통해 작업자 간 목표와 방향성을 맞췄어요. 각 단계마다 주요 목표와 문제점을 내부적으로 투명하게 공유함으로써 작업자 모두가 같은 방향으로 나아갈 수 있었고, 불확실성을 줄일 수 있었죠. 또한 리더십과의 사전 피드백 과정을 통해 프로젝트가 리더십의 기대와 전략적 방향과 일치하는지 점검할 수 있었고, 이를 통해 프로젝트의 중요성과 방향성에 대한 확신을 갖게 되었어요.

유저 스토리 여정의 시각화(Journey Map)을 통해 사용자 경험 전반을 체계적으로 시각화함으로써, 리더십이 사용자가 겪는 불편함과 솔루션의 필요성을 쉽게 파악할 수 있도록 했어요. 이어서 프로토타입을 활용해 눈에 보이는 명확한 솔루션을 제안했는데요. 프로토타입을 통해 실제 화면 흐름과 기능 작동 방식을 보여줌으로써, 리더십이 프로젝트의 최종 목표를 명확히 이해할 수 있도록 돕는 것이 목적이었어요.

또한, 단순히 결과 화면만을 제시하는 대신 해당 솔루션이 도출된 이유와 UX적 관점에서의 필요성을 설명함으로써, 리더십이 이 접근법을 깊이 이해하고 공감할 수 있도록 했어요. 이를 통해 리더십과 비즈니스, 개발 리더들 간에 프로젝트의 필요성과 방향성에 대한 공감대가 형성되었고, 이런 설득의 과정으로 ‘카테고리홈에 검색 기능을 추가’하는 등의 개선 과제가 단순한 선행 아이디어에서 정규 프로젝트로 진행될 수 있었어요.

***\*Internal memo란?***

*인터널 메모는 여기어때에서 프로젝트 진행 시, 프로젝트의 목적, 목표, 범위, 일정, 논의할 사항 등을 정리하여 팀원들이 프로젝트 방향성을 명확히 이해하고 효과적으로 협업할 수 있도록 돕는 문서입니다.*

### 마무리하며

10개월간 선행부터 정규 프로젝트까지 정말 많은 메이커들과 협업이 이루어졌어요. 이번 프로젝트를 통해 특히 느낀 점은, 주기적으로 선행 프로젝트를 진행해 서비스 전반을 깊이 분석하고 이해하는 것이 중요하다는 점이에요. 이런 과정을 통해 개선의 범위를 명확히 그릴 수 있고, 리더십의 공감을 이끌어내며, 메이커들이 공통의 목표로 일관된 결과물을 도출할 수 있었어요. 또, 파생되는 액션 아이템에 대한 맥락을 모든 실무자들과 함께 이해하고 공유할 수 있어 의미가 더욱 컸던 것 같아요.

뿐만 아니라, **설득을 위해선 명확하고 탄탄한 근거가 필수라는 점도 배웠어요. 직관적으로 이해할 수 있는 데이터와 시각화된 결과물을 제시하는 것이 중요했죠.** 그리고 UX 개선을 목표로 하더라도 비즈니스적 고려를 간과해선 안 된다는 점을 다시금 느끼게 되었어요. 이로써 UX와 비즈니스 두 측면을 균형 있게 반영하는 것이 UX Designer의 역할이라는 것을 되새길 수 있었던 프로젝트였어요.
