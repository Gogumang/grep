## 효율적인 Pre-training을 위한 전략: Two staged pre-training

먼저 언어모델(Large Language Model, LLM) 학습 과정은 크게 Pre-training과 Post-training으로 구분됩니다. 상대적으로 Pre-training 과정은 Post-training 대비 아주 큰 Compute budget 이 필요합니다. 예를 들어, 우리가 잘 알고 있는 Meta의 LLM 중 가장 큰 모델인 llama-3.1-405b 모델은 Pre-training 과정에서 15.6T의 Token을 16,000개의 H100 GPU로 54일 동안 학습했습니다. 현실적으로 이렇게 큰 Compute budget을 투자하기는 어렵기에, 저희 조직에서는 효율적인 구조하에 좋은 성능을 내는 LLM을 만드는 데에 집중했습니다. 이에 따라 어떤 크기의 모델을, 어떤 데이터를 이용해서, 어떤 방식으로 학습할지 전략을 구성하였습니다.

사실상 기존 LLM의 학습방식에 따른 Scaling law는 충분한 Compute budget 하에 파라미터의 크기와 학습에 사용하는 데이터를 늘리면 자연스레 성능이 좋아지는 것이기 때문에 저희에게 적절한 방법이 아니었습니다. 저희는 일종의 다른 변수를 통해 Scaling law를 개선할 수 있어야 했습니다. 예를 들어, 학습의 단계를 나누어 서로 다른 Data distribution을 사용하거나, 학습에 사용하는 데이터의 품질에 따라 Scaling law가 개선되어야 했습니다. 결국 여러 방식을 탐색한 끝에 선택한 방식은 **Two staged pre-training**이었습니다.

![](https://images.gogumang.com/0ce2450d15/02.png)

Two staged pre-training은 Pre-training을 두 단계로 나누어서 학습하는 방법으로, Stage 1(Stable stage)와 Stage 2(Decay stage)로 구성됩니다. 각각의 Stage에 서로 다른 Data distribution을 활용해 학습하는 방식입니다. 여기서 “MiniCPM: Unveiling the Potential of Small Language Models with Scalable Training Strategies”라는 논문 결과를 모티브로, 세부 학습 전략을 구성하였습니다. 해당 연구에서는 아래와 같은 Stage 별 Data distribution을 가지고, 전체 1.1T의 Token만 학습하고도 훨씬 크고 더 많은 Token을 학습에 사용한 LLM들(예: llama2-7b)과 거의 비교할 만한 성능을 확보한 것을 확인할 수 있습니다.

![](https://images.gogumang.com/0ce2450d15/03.png)

## Two staged pre-training 을 위한 데이터 전략

Two staged pre-training 방식은 각 Stage에 따라 Data distribution을 다르게 학습하기 때문에 해당 Stage에 적합한 데이터 수집과 전처리 과정이 중요합니다. 일반적으로 Stage 1 학습에서는 특정 도메인을 목표로 하지 않고 다양한 도메인을 포괄적으로 다룰 수 있는 데이터(예: CommonCrawl)를 주로 사용하며, 전체 Pre-training 학습 관점에서 더 많은 학습 시간을 할당합니다. 반대로 Stage 2에서는 Stage 1에 비해 더 적은 학습시간을 할당하며, 특정한 도메인을 다루는 데이터(예: arXiv)를 더 많이 사용하거나, 상대적으로 LLM 학습에 도움이 될 만한 고품질의 데이터를 기존 대비 더 많이 사용합니다.

### 1. 데이터 수집

각 Stage에 적합한 데이터를 구성하기 위해 “해당 말뭉치를 LLM 학습에 사용하는 목적”을 크게 4가지로 정의했습니다. Stage마다 데이터의 목적을 반영한 Data distribution 탐색을 하기 위해서는 목적에 따라 말뭉치를 분류하여 데이터화하는 과정이 필요했습니다. 이 과정에서 LLM 학습에 사용해도 문제가 없는 라이센스(예: apache-2.0, cc-by-4.0)에 해당하는 말뭉치들만 수집하여 데이터화하였습니다.

|                목적                 |          학습에 사용 가능(예시)           |               학습에 사용 불가능(예시)                |
|-----------------------------------|----------------------------------|---------------------------------------------|
| common sense \& general knowledge | 모두의 말뭉치 (국립국어원)                  | 저작권이 있는 신문 기사                               |
| stem                              | 대규모 구매 도서 기반 한국어 말뭉치 데이터 (AI 허브) | KCI 논문들                                     |
| code                              | permissive license에 해당하는 코드 뭉치들  | no license이거나 permissive license가 아닌 코드 뭉치들 |
| wikipedia                         | 한국어 위키피디아                        | 나무위키                                        |

### 2. 데이터 전처리

이렇게 수집한 5T가량의 데이터를 각 Stage의 목적에 따라 각기 다른 전처리 과정을 수행하였습니다.

#### 1) 목적이 Common sense \& General knowledge인 경우

Common sense \& General knowledge 데이터의 경우 FineWeb, DataComp-LM과 같은 논문에서 사용한 전처리 과정을 적용하였습니다. 이 과정에서 혹여라도 데이터에 존재할 수도 있는 민감한 개인정보를 처리하기 위해 개인정보 익명화 및 제거도 같이 수행하였습니다.

![](https://images.gogumang.com/0ce2450d15/05.png)

이렇게 기본적인 데이터 전처리를 수행한 뒤, Stage 2에 사용할 고품질 데이터를 선별하기 위해 데이터 Quality를 점수화하는 시도를 거쳤습니다.

먼저 한국어 데이터에 대해서는 “The FineWeb Datasets: Decanting the Web for the Finest Text Data at Scale”에서 제시된 방식과 유사하게 일종의 Quality를 측정하는 Edu scorer를 만들었습니다. 해당 연구에서는 데이터가 얼마나 교육적인지를 데이터의 Quality로 간주하고, Quality의 점수가 높은 것을 활용하는 것이 LLM 학습에 매우 유용함을 보였습니다.

![](https://images.gogumang.com/0ce2450d15/06.png)

이때, Edu scorer를 만드는 파이프라인은 아래와 같습니다. 데이터셋에서 샘플을 적당히 가져오고, 이를 llama-3.1-70b와 같은 LLM에 아래와 같은 프롬프트와 함께 데이터를 전달하여 Quality 점수를 측정합니다. 측정한 Quality 점수를 기반으로 High educational, Low educational로 샘플을 분류하고, 이를 작은 적당한 모델로 학습합니다. 저희가 참고한 연구에서는 Embedding 모델을 기반으로 Regression head를 붙여서 학습했지만, 저희는 GPU를 사용하지 않고, CPU만으로 대량의 추론을 통해 데이터의 Quality 점수를 측정하기 위해 FastText를 이용하여 Edu scorer를 학습하였습니다.

![](https://images.gogumang.com/0ce2450d15/07.png)

Edu scorer를 이용해서 선별한 High educational 데이터셋과 임의로 뽑은 데이터셋으로 각각 llama-3-8b 모델을 같은 양의 Token을 학습하여 비교해 본 결과, Edu scorer로 선별한 데이터셋이 LLM 학습에 있어서는 상대적으로 Quality가 좋아서, Stage 2 용 데이터셋을 충분히 구성할 수 있음을 확인할 수 있었습니다.

![](https://images.gogumang.com/0ce2450d15/08.png)

영어 데이터의 경우, “DataComp-LM: In search of the next generation of training sets for language models” 연구에서 활용한 FastText 기반의 Quality 관련 모델을 사용하여, Stage 2를 위한 High quality 데이터를 선별하였습니다.

![](https://images.gogumang.com/0ce2450d15/09.png)

#### 2) 목적이 Code인 경우

Code 데이터는 먼저 Stage 1 데이터셋을 구성할 때는 오픈소스 코드 말뭉치인 starcoderdata, TheStackV2에서 Permissive license에 해당하는 데이터만 선별하여 구성하였습니다. 특히 TheStackV2는 여러 버전이 존재하는데, 저희는 코드 전용 모델을 만드는 것이 아니므로 최소한의 프로그래밍 언어에 관련된 데이터만 가지고 있는 train-smol-ids 버전에서 Permissive license인 데이터를 선별하였습니다. 이 과정에서 TheStackV2의 Token의 양이 434B에서 133B로 줄었습니다.

Stage 2의 데이터셋을 구성할 때는 Stage 1을 구성한 데이터셋에서 Python과 관련된 코드 데이터만 사용하였고, 거기에 덧붙여 자연어와 코드가 적절히 섞여 있는 데이터, Instruction following을 위한 Supervised Fine-tuning(SFT) 데이터셋을 추가하였습니다. 특히 SFT 데이터셋의 경우 LLM의 성능 평가를 위한 벤치마크의 평가 데이터를 포함하거나 유사한 데이터가 존재할 가능성이 있기에, 데이터셋의 목적과 일치되는 벤치마크에 Decontamination 작업을 수행해야 합니다. 따라서 저희는 Humaneval, MBPP 벤치마크에 Decontamination을 수행하였습니다.

## Two staged pre-training 학습 전략

데이터 수집과 전처리 과정을 거친 후, 저희는 Compute budget을 고려하여 Two staged pre-training의 전체 학습 Token budget을 3T Token으로 하고, Stage 1과 Stage 2에서 각각 2.7T, 0.3T Token을 사용해서 Kanana Essence를 먼저 Pre-training 하는 것으로 결정하였습니다.

Kanana Essence의 구조는 사실상 업계에서 표준인 llama와 유사한 구조(예: Grouped query attention, RoPE 등)로 선정하였으며, 8K Context length를 가지도록 학습하는 것을 계획했습니다. 학습 방식은 “DeepSeek LLM: Scaling Open-Source Language Models with Longtermism” 연구에서 제시한 방법론들을 활용하였습니다. 해당 연구에서 제시한 Hyperparameter에 대한 Scaling law를 활용하여, Learning rate와 Batch size 등을 결정하였습니다. 특히 Learning rate scheduler의 경우, 기존에 많은 연구들에서 활용하는 Cosine learning rate scheduler 아닌 Multi-step learning rate scheduler를 사용하였습니다. 그 이유는 연구에서 제시된 바와 같이 Cosine learning rate scheduler를 사용할 때보다, 더 낮은 Train loss를 달성할 수 있기 때문입니다.

![](https://images.gogumang.com/0ce2450d15/13.png)

Kanana Nano는 비용 효율적으로 학습하기 위해 “Compact Language Models via Pruning and Knowledge Distillation” 연구에서 제시한 Pruning \& distillation 기법으로 학습하는 전략을 채택하였습니다. 해당 연구에서 제시한 결과를 보면 4B 크기의 LLM을 처음부터 From scratch로 만드는 것보다, 이미 학습된 15B 크기의 LLM으로부터 Pruning \& distillation 기법을 적용하여 학습하는 것이, 훨씬 적은 Token을 학습에 사용하고도, 더 좋은 성능을 달성하는 것을 확인할 수 있습니다.

![](https://images.gogumang.com/0ce2450d15/14.png)

결론적으로 Kanana Essence를 먼저 학습하고, 이후 Pruning \& distillation 기법으로 Kanana Nano를 학습하는 것으로 두 모델을 확보하는 전략을 채택하였습니다. 두 모델을 확보하는 파이프라인은 아래와 같습니다.

![](https://images.gogumang.com/0ce2450d15/15.png)

### 1. Kanana Essence 학습

Kanana Essence는 서비스에 가장 최적화된 중형 사이즈의 모델입니다. 이와 같은 전략에서 가장 중요한 것은 먼저 학습하는 Kanana Essence의 성능을 최대화하는 것이었습니다. 이를 위해 각각 Stage 별로 목표를 두고, 각 목표에 맞게 학습의 효율을 끌어올릴 수 있는 데이터셋의 목적에 따른 Data distribution 탐색이 필요했습니다.

#### Stage 1 Data distribution 탐색 및 학습

Stage 1의 목표로서 학습의 성능을 최대화해야 하는 벤치마크로, 한국어의 경우는 kmmlu와 haerae를 영어인 경우 mmlu로 선택하였습니다. 한국어의 경우 특별히 haerae가 추가된 이유는 과거 연구에서 kmmlu가 한국의 Cultural knowledge를 요구하는 정도가 생각보다 그 비율이 적고, 반대로 haerae가 더 높다고 생각되는 결과들이 보고된 바 있기 때문입니다. “HAE-RAE Bench: Evaluation of Korean Knowledge in Language Models” 연구에서 한국어 말뭉치로만 학습된 Polyglot-ko 모델이 LLAMA-2와 같은 LLM 대비 훨씬 높은 성능을 기록한 바 있습니다. 반면에 “KMMLU: Measuring Massive Multitask Language Understanding in Korean” 연구에서는 kmmlu 벤치마크가 한국에 관한 Cultural knowledge를 요구하는 Task가 20% 정도라고 보고되었습니다.

![](https://images.gogumang.com/0ce2450d15/16.png)

따라서 한국에 관한 Cultural knowledge를 좀 더 적절히 고려하기 위해 kmmlu, haerae, mmlu 세 가지 벤치마크 점수의 평균을 최대화하는 Data distribution을 찾고자 하였고, 250B를 학습하여 Data distribution을 검증하는 Ablation을 진행하였습니다. Ablation 목록은 표와 같습니다.

| Ablation 1            | 목적이 Common sense \& general knowledge인 한국어 Token들을 절반만 사용함.                     |
| Ablation 2            | 목적이 Common sense \& general knowledge인 한국어 Token들을 Multi-epoch (2 Epochs)로 사용함. |

#### Stage 2 Data distribution 탐색 및 학습

Stage 1 학습의 결과에서 수학과 코드 관련 성능을 개선하기 위해, 여러 가지 Ablation을 진행했습니다. 특히 수학과 코드 관련 성능을 개선하는 것뿐만 아니라, Stage 1에서 목표로 했던 벤치마크들인 mmlu, kmmlu, haerae 등도 최소 성능을 유지해야 했기 때문에, gsm8k, humaneval, MBPP 벤치마크 등을 추가해서, 6개의 벤치마크의 점수 평균을 올리는 최적의 Data distribution을 찾고자 하였습니다.

또한 Stage 1과 달리 Stage 2에서는 상대적으로 적은 0.3T Token의 학습만 하므로, Compute budget을 나누어 여러 Ablation 들을 병렬적으로 학습하는 것이 가능하였습니다. 결론적으로 17가지의 Ablation을 통해서 llama-3.1-8b보다 벤치마크 점수 평균이 훨씬 높은 경우를 찾을 수 있었습니다.

### 2. Kanana Nano 학습

Kanana Nano 모델은 모바일 디바이스에서도 활용 가능한 초경량 모델입니다. Pruning \& distillation 방식으로 Kanana Nano를 학습하기에 앞서 Baseline으로서 비교 대상이 필요하였고, 이를 위해서 Kanana Essence에서 사용한 레시피를 활용하여 From scratch로 학습을 먼저 수행했습니다. Kanana Nano로 염두에 둔 Arhitecture는 역시 llama와 유사한 구조로 Kanana Essence와 비교해 보면 아래의 표와 같습니다.

|                 | Kanana Essence | Kanana Nano |
|-----------------|----------------|-------------|
| Tie embedding   | False          | False       |
| Context length  | 8k             | 8k          |
| Hidden layers   | 32             | 32          |
| Attention heads | 32             | 16          |
| Key value heads | 8              | 8           |

학습된 모델을 비슷한 크기의 llama-3.2-3b와 비교했을 때, 아래의 표와 같이 상회하는 성능을 보여 학습에 사용한 레시피가 적절하게 최적화되어 있음을 다시 한번 확인할 수 있었습니다.

#### Pruning \& distillation

“Compact Language Models via Pruning and Knowledge Distillation” 연구에서는 Pruning \& distillation을 제안하면서 이 기법을 사용할 때 참고할 수 있는 Best practice를 아래의 이미지와 같이 제시하고 있습니다.

![](https://images.gogumang.com/0ce2450d15/26.png)

저희는 실제로 이 기법을 활용하는 데 있어 Best practice에 따라 Pruning \& distillation을 수행하였습니다. Width pruning을 사용하고, Teacher의 Logit만으로 Distillation 학습을 수행했으며, Two staged pre-training 중 Stage 2에 활용한 데이터만 사용하였습니다. 특히 유의미했던 것은 1번과 8번 항목으로 Kanana Essence에서 바로 Kanana Nano로 Pruning \& distillation을 시도했을 때, Kanana Essence에 Pruning을 적용하여 Kanana Nano를 초기화할 경우 학습에 실패했습니다.

결론적으로 Best practice의 1번과 8번 항목을 참고하여 Kanana Nano보다는 크지만, Kanana Essence보다는 작은 크기의 중간 모델을 Kanana Essence로부터 Pruning \& distillation을 적용해서 학습했습니다. 해당 모델로부터 Pruning을 하고, Kanana Essence로부터 Distillation 학습을 수행해서 Kanana Nano 학습에 성공하였습니다. 이 과정을 통해서 학습한 Kanana Nano의 성능은 아래와 같습니다.

## Further Work

향후 Kanana Essence, Nano의 성능을 개선하기 위해 자체 학습한 LLM의 부족한 점을 파악해야 했습니다. 이를 위해 오픈소스 모델 중 llama-3.1-8b를 제외하고, 비슷한 크기의 다른 모델인 gemma-2-9b, qwen2-7b 모델과 영어 및 한국어 관련 벤치마크 중 mmlu, kmmlu 벤치마크의 영역별 성능을 비교했습니다. mmlu에서는 Kanana Essence가 Stem과 Social sciences 영역에서 두 모델 대비 상대적으로 낮은 점수를 기록하는 것을 확인하였고, kmmlu에서는 Stem과 Applied science 영역에서 상대적으로 낮은 점수를 보이는 것을 확인하였습니다.

![](https://images.gogumang.com/0ce2450d15/28.png)

![](https://images.gogumang.com/0ce2450d15/29.png)

mmlu에서 Stem과 Social sciences 영역에 속하는 세부 Task들의 성능을 비교했을 때, gemma-2-9b, qwen-2-7b가 수치계산이 필요한 Task에서 Kanana Essence 대비 잘하는 Task가 많음을 확인할 수 있었습니다. 구체적으로 Stem 영역에서는 High school statistics, High school physics, Elementary mathematics 등이 Kanana Essence 대비 두 모델이 20% 이상 성능이 좋고, Social sciences 영역에서는 High school microeconomics, Econometrics 등의 Task에서 20% 이상 성능이 좋았습니다. 이는 Kanana Essence의 학습 데이터를 구성하는 과정에서 지식을 요구하는 영역과 관련된 말뭉치가 부족하지만, 그중에서도 특히 수치계산 관련 말뭉치들이 부족했음을 시사합니다.

두 모델과의 비교 분석을 통해서 지식과 관련된 말뭉치뿐만 아니라 수치계산이 필요한 도메인에 관련된 말뭉치 보강에 대한 필요성을 느끼고, 현재 관련 데이터를 “DeepSeekMath: Pushing the Limits of Mathematical Reasoning in Open Language Models” 연구와 유사하게 CommonCrawl에서 직접 수집하고 처리하는 방식으로 데이터를 보강하고 있습니다. 더불어 Code 관련 말뭉치의 경우도 Quality가 좋은 말뭉치의 부족함을 느끼고, “DeepSeek-Coder: When the Large Language Model Meets Programming - The Rise of Code Intelligence” 연구와 같은 방식(예: Dependency parsing)을 차용하여 개선하고 있습니다.

![](https://images.gogumang.com/0ce2450d15/34.png)

마지막으로 “Textbooks Are All You Need”, “Textbooks Are All You Need II: phi-1.5 technical report” 등의 연구와 같이, 특정 도메인(예: 우리의 경우 Stem, Code)에 대해 High quality의 Synthetic dataset을 생성해 데이터를 개선하여 학습하는 것을 목표로 하고 있습니다. 두 연구를 기초로 확장된 연구인 “Phi-3 Technical Report: A Highly Capable Language Model Locally on Your Phone” 연구에서 High quality의 Synthetic dataset으로 Web에서 직접 모은 Dataset의 품질을 개선한 결과, Scaling law를 개선하여 효율적으로 학습할 수 있음을 보여주었습니다.

![](https://images.gogumang.com/0ce2450d15/35.png)

결론적으로 모델의 구조를 개선하거나 크기를 키우는 데에 선행하여, Kanana Essence, Nano를 학습하는 데 사용한 데이터에서 상대적으로 부족한 영역의 데이터를 개선하는 여러 가지 방식으로 진행하고 있습니다. 또한, 이 학습 노하우를 바탕으로 Kanana LLM 중 가장 큰 모델인 Kanana Flag도 학습을 진행하고 있습니다. 앞으로도 카카오는 개선된 Scaling law로 더 좋은 LLM을 학습해 나갈 것입니다.

지금까지 카카오의 자체 언어모델, Kanana LLM의 Pre-training 과정과 성능을 소개했습니다. 이어지는 글에서는 이 베이스 모델을 바탕으로 어떻게 사용자의 명령을 잘 이해하고 따를 수 있게 만드는지 LLM의 Post-training 과정과 성능 결과를 공유할 예정입니다.
