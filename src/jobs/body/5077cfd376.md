### 합류하면 함께 할 업무예요  
- 웹과 네이티브가 만나는 지점을 설계해요.  
- 화면과 시스템의 상태를 측정할 수 있게 만들어요. 트레이싱·로깅·에러 진단 체계를 세워 장애의 원인을 추측이 아니라 데이터로 찾아요.  
- 수백 개의 서비스를 지탱하는 모노레포와 빌드 툴체인을 만들어요. 빌드·배포 시간, 의존성 구조, 로컬 개발 환경을 개선해요.  
- 테스트하기 어려운 것을 테스트 가능하게 만들어요. 디바이스 팜, E2E 실행 환경처럼 개인의 노력이 아니라 구조로 푸는 일을 해요.

### 지금까진 이런 일을 했어요  
- yarn berry 기반의 모노레포인 토스뱅크 프론트엔드 각 서비스를 standalone 방식으로 빌드되도록 변경하여 도커 이미지 사이즈를 1/10로 줄여서 빌드시간을 단축했어요.  
- API URL을 수정하려고 할 때, 해당 API가 정상적인 응답을 주는지 체크하도록 CI 스크립트를 추가했어요. 휴먼에러로 서비스 장애가 생기지 않는 안전장치 역할을 하고 있어요.  
- 프론트엔드 어드민을 구축해서 배포를 좀 더 편하게 할 수 있게 하고, 리다이렉트 로직이 필요한 경우 이 어드민에서 설정할 수 있게 했어요. DX를 위한 기능을 이 어드민에 추가하고 있어요.  
- 각종 설정 파일, CI/CD 스크립트를 작성해서 모노레포 안의 서비스들이 동일한 설정과 배포환경을 가질 수 있게 했어요.

### 이런 분과 함께하고 싶어요  
- WebView, React Native 등 네이티브와 웹이 맞닿는 레이어를 다뤄본 경험이 있으신 분을 찾고 있어요.  
- 로깅·트레이싱·에러 모니터링 등 클라이언트 관측 체계를 직접 세워본 경험이 있으신 분을 기대해요.  
- 모노레포, 번들러, CI 같은 빌드 툴체인을 직접 개선해본 경험이 있으신 분을 찾고 있어요.  
- 테스트 가능성을 개인의 습관이 아니라 설계의 문제로 바라보는 분이면 좋아요.  
- "지금 하는 일을 어떻게 더 잘할까"를 스스로 고민해 결과로 만들어본 경험이 있는 분이 필요해요.  
- 자동화·툴링·테스팅으로 개발 환경 자체를 개선해본 경험이 있다면 좋아요.
