### 토스 서버의 조직 구조를 알려드려요  
- 토스의 Server Developer는 Product, Platform, Productivity 세 개의 Chapter로 나뉘어 일합니다. 직무명은 모두 같지만, 각 Chapter마다 집중하는 업무 영역에 차이가 있어요.  
- **Productivity Chapter**는 토스 팀원들이 손으로 작업하는 수많은 유즈 케이스를 시스템이 대신 수행할 수 있도록 범용 도구를 개발해요. 특정 서비스 하나를 개선하는 것이 아니라 팀이 일하는 방식 자체를 바꾸는 일이라, 도구 하나가 조직 전체의 속도를 끌어올리는 결과로 이어집니다.  
- 비즈니스, 컴즈, 컴플라이언스, 인프라, 데이터까지 토스가 필요로 하는 모든 영역이 대상이에요. 특정 도메인에 갇히지 않고, 토스 팀에서 발생하는 문제를 찾아 기술적인 제품으로 해결하는 데 집중합니다.  
- 토스 서버 조직에 대해 더 알아보고 싶다면? [→ *토스 Server Chapter Wiki 바로가기*](https://tosspublic.notion.site/Server-Chapter-Wiki-30d714bbfde7802a8919ebec749dad67)

### 합류하면 함께할 업무예요  
- MSA로 개별 구성되는 어드민 서비스가 빠르게 구현될 수 있도록 돕는 프레임워크를 개발해요.  
- 쉬운 사용성으로 높은 보안 요건들을 충족시키기 위한 도구를 개발하고 있어요.  
- 개발한 제품들이 토스 계열사 전체에 잘 배포될 수 있도록 인터널 시스템의 빌드, 배포 파이프라인을 구축하고 운영해요.

### 이런 분과 함께하고 싶어요  
- 토스 팀원의 생산성을 향상시키기 위해서는 팀 문화를 온전히 이해해야 해요. 조직문화에 대한 관심이 많고, 관찰을 통해 문화를 주도적으로 이끌어 나가고자 하는 분을 기다리고 있어요.  
- 비즈니스 요구 사항을 정확하게 이해하며, 능숙하게 데이터 모델과 API를 설계할 수 있는 분이 필요해요.  
- 장애를 경험하고 문제를 해결해보신 경험이 있는 분이 필요해요.  
- 서비스 개발을 하면서 얻게 되는 새로운 인사이트를 공유하며, 끊임없이 기술적인 도전을 하고 싶은 분과 함께하고 싶어요.

### 이력서는 이렇게 작성하시는 걸 추천해요  
- 복잡도 높은 비즈니스 문제를 발견해서 적극적으로 개선해본 경험이 있다면, 어떤 기술 스택을 사용하여 어느 정도 개선했는지 구체적으로 적어주세요.  
- 어떤 프로젝트를 진행하였는지에 대한 나열식 기술보다는 기여도가 높은 프로젝트에 대해 문제 의식부터 가설 설정 / 해결 방식 / 결과 / 어려웠던 점 등의 자세한 내용을 작성해주세요.  
- 서비스 초기단계에 참여해본 경험이 있다면 기술해주세요.

### 함께할 동료를 위한 한마디  
> "토스의 Server Productivity Chapter는 토스의 생산성 향상을 통해 고객의 경험에 기여하고 있어요."  
- 어떻게 일을 해야 할지, 또 이미 만들어진 제품 안에서도 생산성을 더 줄일 수 있는 부분은 없을지 끊임없이 고도화하고 집착합니다. 가끔은 하지 않아도 되는 일을 찾아내어 제거하기도 하죠. 어쩌면 토스팀 전체의 속도를 끌어올리는 일까지도 Server Productivity 챕터가 기여할 수 있는 부분이라고 생각해요.  
- 팀의 생산성을 높이는 챕터의 가치관은 나아가 고객의 경험에 긍정적인 영향을 준다고 생각해요. 내부 구성원을 위한 제품을 만드는 것에 큰 희열을 느끼고, 잃어버린 생산성을 1분씩 모아 몇만 분의 시간을 절약한다면 토스의 고객도 더 좋은 서비스를 경험할 수 있기 때문이에요. 팀원들의 생산성을 높여준다는 사실만으로 또 다른 동력을 얻을 수 있는 분이라면 Server Productivity 챕터에서 함께 일해봐요!
