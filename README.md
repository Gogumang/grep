# grep

**기술 블로그 읽기. 여러 회사의 새 글을 한곳에서 훑고, 찾고, 그 자리에서 읽습니다.**

→ **https://grep-alpha.vercel.app**

---

## 읽는 흐름

**훑기** — 첫 화면 맨 위의 *오늘의 픽*은 블로그가 겹치지 않게 고릅니다.
한 회사 글이 몰려서 나머지를 덮는 일이 없습니다. 그 아래로 최신 글이 이어지고,
왼쪽에서 분류(Engineering·Design·Product)와 블로그 이름으로 좁힐 수 있습니다.

**찾기** — `⌘K`(또는 헤더의 돋보기)로 검색창이 열립니다. 제목만이 아니라
**글 본문 전체**를 찾기 때문에 "그때 캐시 얘기 나온 글이 어디였더라"가 됩니다.
손을 키보드에서 뗄 일이 없습니다 — 방향키로 결과를 오르내리고, `Enter`로 열고,
`Esc`로 닫습니다.

**읽기** — 목록에서 글을 열면 본문이 그 자리에서 읽힙니다.
코드 블록과 이미지도 원문 그대로입니다. 탭을 새로 열고 로딩을 기다릴 필요가 없습니다.

## 읽는 걸 방해하지 않으려고 한 것들

읽기 좋은 사이트는 기능이 많은 사이트가 아니라 **걸리적거리지 않는 사이트**입니다.
그래서 이런 것들을 챙겼습니다.

- **깜빡이지 않는 다크 모드** — 화면이 그려지기 전에 테마가 정해집니다.
  다크 모드로 들어왔는데 흰 화면이 한 번 번쩍이는 일이 없습니다.
  처음엔 OS 설정을 따르고, 한 번 바꾸면 그 선택을 기억합니다.
- **필요할 때만 받는 검색** — 검색을 쓰지 않는 사람은 검색 코드를 내려받지 않습니다.
  검색창을 처음 열 때 받아옵니다.
- **가벼운 글 페이지** — 글을 읽는 화면에는 UI 프레임워크가 없습니다(압축 후 2.1KB).
  본문이 뜨기까지 기다릴 자바스크립트가 없습니다.
- **줄어든 이미지** — 썸네일도 본문 이미지도 원문 서버에서 받아 AVIF로 다시 만들어
  함께 내보냅니다(246장, 90MB → 8.7MB). 원문이 이미지를 지워도 글이 비지 않고,
  읽는 사람의 브라우저가 원문 서버로 요청을 보내지 않습니다.
  `bun run images`로 새로 수집된 글의 이미지를 받아옵니다.
- **화면 크기를 가리지 않음** — 폰에서 목록을 훑다가 노트북에서 이어 읽어도 같습니다.

## 원문이 먼저입니다

남의 글을 옮겨 싣는 곳이라, 읽는 사람과 쓴 사람 모두에게 정직하려고 합니다.

- 모든 글에 **글쓴이와 출처 블로그**를 함께 답니다
- 글 위에 **원문에서 보기** 링크를 둡니다
- 검색엔진과 AI에게 **정본은 원문이라고 알립니다**(`canonical`이 원문을 가리킵니다)

여기는 찾는 곳이고, 읽는 곳은 원문이어도 좋습니다.

## 채용 · 이벤트

**채용**(`/jobs`) — 기술블로그를 운영하는 회사들의 **개발 직군** 공고를 모읍니다. 사람이 한 건씩 보고 올린 공고만 실립니다.
공고를 열면 본문이 그 자리에서 읽히고, 지원은 **원문에서 지원하기** 링크로 각 회사 채용 페이지에서 합니다.
글과 마찬가지로 공고 페이지의 `canonical`은 원문 공고를 가리킵니다. 마감이 지난 공고는 보이지 않습니다.
수집은 collector(grep-airflow)가 매일 하고, 어드민의 채용 검증 화면에서 공개한 공고를 collector가
[`src/jobs/jobs.json`](src/jobs/jobs.json)과 `src/jobs/body/`에 커밋합니다 — 이 저장소에서는 공고 파일을 손으로 만지지 않습니다.
원문에서 마감된 공고는 collector가 다음 수집 때 사이트에서 내립니다.

**이벤트**(`/events`) — 개발자 컨퍼런스·밋업·해커톤 일정을 [티켓타코](https://ticketa.co)에서 모읍니다.
collector(grep-airflow)가 매일 티켓타코 행사를 읽어 개발 행사만 골라 [`src/events/events.json`](src/events/events.json)에
커밋합니다 — 이 저장소에서는 행사 파일을 손으로 만지지 않습니다. 끝난 행사는 빌드와 화면에서 알아서 빠집니다.
페이지에는 그중 [`src/events/config/featured.ts`](src/events/config/featured.ts)에 적은 행사만 이미지와 함께 올립니다 —
이미지는 `public/events/`에 두고, 티켓타코 이용약관(제11조)상 가능하면 주최 측 공식 사이트 이미지를 씁니다.
신청은 티켓타코 행사 페이지에서 합니다.
다른 행사 모음(Dev-Event 등)은 사용 정책상 옮겨 올 수 없습니다.

## 책상 꾸미기

**책상**(`/desk`, 준비 중) — 메뉴·사이트맵에 없고 검색엔진에도 싣지 않아(`noindex`) 주소로만 들어갑니다.
개발자 책상을 3D로 꾸밉니다. 모니터·키보드·마우스·음료·식물·조명·소품을 올리고,
끌어서 옮기고(5cm 격자에 맞춰 붙습니다), 돌리고, 같은 종류의 다른 물건으로 바꿔 볼 수 있습니다.
물건끼리 겹치거나 책상 밖으로 나가지 않습니다. 선택한 물건은 방향키로 5cm씩(Shift는 20cm), `R`로 회전, `Delete`로 뺍니다.

서버 없이 동작합니다 — 꾸미는 책상은 브라우저(localStorage)에 저장되고, 주소창은 건드리지 않습니다.
**링크 복사**를 누를 때만 배치를 링크 `#` 뒤에 담습니다(`v1.oak.monitor-27:0:-20:0,...`). 받은 사람은 그 책상을 둘러보고
"이 책상으로 시작"하거나 "내 책상으로" 돌아갑니다 — 남의 링크를 열었다고 내 책상이 덮어써지지 않습니다. 이미지로도 저장할 수 있습니다.
키보드·마우스·스탠드는 하나만(새로 고르면 바뀜), 모니터는 두 대까지처럼 분류마다 올릴 수 있는 개수가 정해져 있습니다.
three.js는 이 페이지에서만 내려받고(다른 페이지 무게는 그대로), 모델은 책상에 올린 물건 것만 받습니다.

- **재질·조명·스캔 모델** — `bun run desk-assets`가 [Poly Haven](https://polyhaven.com)(CC0)에서 받아
  압축(meshopt, WebP 1024px)한 뒤 `public/desk/`에 두고 출처를 [`src/desk/assets.json`](src/desk/assets.json)에 적습니다.
  페이지의 "3D 모델·재질 출처"가 이 파일을 그대로 보여 줍니다.
- **스캔 모델이 없는 물건**은 `src/components/desk/itemModels.tsx`의 기본 도형 모델로 그립니다. 모델을 받는 동안이나 받지 못했을 때도 이걸로 자리를 지킵니다.

모델은 원본 크기·단위와 상관없이 카탈로그의 칸(가로×세로 cm)에 맞춰 줄여 그립니다 — 물건 크기를 바꾸려면 모델이 아니라
[`src/desk/catalog.ts`](src/desk/catalog.ts)의 칸을 고칩니다. id는 이미 퍼진 링크에 들어 있으니 바꾸거나 지우지 않습니다.

맨 위에 올릴 글을 직접 고르고 싶다면
[`src/posts/config/picks.md`](src/posts/config/picks.md)에 원문 주소를 적으면
그 순서대로 올라갑니다. 비워두면 자동 선정이 대신합니다.
